# Massbility 强制移动策略 TODO

## 背景

当前 `UMassForcedMovementSubsystem` 支持 `Velocity`、`Displacement` 和 `ToLocation` 三种模式，但核心积分结果是线性的：速度恒定，位移按 Tick 平均分配，目标位置按直线插值。碰撞处理通过 `IMassMovementAdapter` 扩展，默认系统本身不提供加减速、曲线、重力或轨迹控制。

本文只记录后续待设计和验证的强制移动策略，不代表已经选择具体 API 或实现方案。

## 目标与约束

- [ ] 保持 Mass 数据导向特性；运行时使用固定容量数据、ID、Handle 和预编译策略，避免每实体 UObject、动态分配和 GameplayTag 查找。
- [ ] 强制移动仍只负责表达和积分移动意图；最终碰撞解析和 `TransformFragment` 写入保持在 Movement Processor / Adapter 边界内。
- [ ] 相同输入、Tick 率和碰撞结果下保持确定性，支持回放、网络同步和测试复现。
- [ ] 新增策略不破坏现有 `Replace`、`Additive`、`RejectIfActive` 仲裁语义。
- [ ] 已开始的移动不能因为 LOD 或查询裁剪被静默丢失。

## 待支持的移动策略

### 1. 非线性速度曲线

- [ ] 支持 `EaseIn`、`EaseOut`、`EaseInOut` 和自定义预编译曲线。
- [ ] 曲线输入使用归一化进度 `0..1`，输出位移比例或速度比例。
- [ ] 对 `Displacement` / `ToLocation` 使用位移曲线，确保最终总位移不会因曲线积分误差而偏离目标。
- [ ] 明确曲线在暂停、阻挡、替换和剩余时间变化时的重采样规则。

### 2. 加速度与减速度

- [ ] 支持初速度、目标速度、最大加速度、最大减速度。
- [ ] 支持击退前段快速推出、后段减速停下的运动模型。
- [ ] 明确速度模式与位移模式之间的转换规则，避免同一请求同时解释为速度和总位移。
- [ ] 对速度和加速度设置上限，防止异常请求产生 NaN、Inf 或过大位移。

### 3. 轨迹型移动

- [ ] 支持抛物线 / 弧线移动，用于击飞、跳跃和投掷。
- [ ] 支持沿方向的水平位移与独立的垂直高度曲线。
- [ ] 可选支持二次或三次样条轨迹，但运行时只保存固定数量的控制参数或编译后的轨迹 ID。
- [ ] 明确轨迹遇到碰撞时是停止、截断、沿表面滑动还是重新规划。

### 4. 目标跟随与动态目标点

- [ ] 支持目标位置在移动期间持续跟随，而不是只读取初始位置。
- [ ] 支持目标 Entity、Actor 或外部代理的安全采样边界。
- [ ] 目标失效时提供 `Stop`、`FinishAtCurrent` 和 `Cancel` 等结束策略。
- [ ] 明确动态目标跟随与 `ToLocation` 的优先级、预测和网络同步语义。

### 5. 旋转与朝向

- [ ] 支持移动期间保持原朝向、朝向位移方向或朝向目标。
- [ ] 支持角速度、最大转向速度和角度曲线。
- [ ] 明确是否由同一个 Movement Adapter 写入旋转，避免多个系统同时写 `TransformFragment`。

## 仲裁与组合

- [ ] 将移动请求拆分为平移、垂直运动和旋转通道，评估是否允许不同通道独立叠加。
- [ ] 对 `Additive` 支持不同方向 Velocity 的向量合成，并定义优先级和最大合成速度。
- [ ] 支持“不可打断”或“仅可被更高优先级打断”的移动标志。
- [ ] 替换活动移动时，明确是否继承当前位置、当前速度、剩余时间和碰撞状态。
- [ ] 为冲刺、击退、拉拽、传送、跳跃等玩法提供通用策略组合，不把玩法名称写入核心枚举。

## 碰撞与环境适配

- [ ] 提供默认 Kinematic Adapter，至少支持停止、滑动和忽略碰撞。
- [ ] 支持连续碰撞检测或子步进，避免高速击退穿透墙体。
- [ ] 明确碰撞阻挡后的进度：暂停、结束、重新计算剩余位移或沿切线继续。
- [ ] 统一 Adapter 的 `AppliedDelta`、`bBlocked`、`bFinished` 和失败原因语义。
- [ ] 评估与 MassMovement、Nav、ZoneGraph、CharacterMovement 以及外部 GAS Avatar 的适配边界。
- [ ] 外部目标无法被本地 Transform 直接修改时，必须返回明确的 Unsupported 结果，不修改 Proxy 状态。

## 数据模型与性能

- [ ] 将策略编译为紧凑的策略 ID、固定参数和运行时状态，避免每 Tick 虚函数调用。
- [ ] 评估 `FMassForcedMovementFragment` 是否需要保存当前速度、归一化进度、曲线 ID、轨迹状态和碰撞子步进余量。
- [ ] 对高频群体击退进行批量积分和批量 Adapter 查询压测。
- [ ] 为请求队列、活动移动数、阻挡数、完成数、策略类型和失败原因增加可观测统计。
- [ ] 验证 Tick 追赶、暂停、时间缩放和服务器校正时不会重复或跳过位移。

## 验证用例

- [ ] 线性 `Displacement` 在不同 Tick 率下最终位置一致。
- [ ] `EaseInOut` 位移曲线最终精确到达目标位置。
- [ ] 抛物线移动的水平位移、最高点和落点符合配置。
- [ ] 高速移动撞墙时不会穿透，且 `Stop` / `Slide` 结果稳定。
- [ ] 活动移动被更高优先级请求替换后，不产生额外位移或重复积分。
- [ ] `Additive` 组合不会超过配置的最大速度或位移预算。
- [ ] 目标死亡、销毁、变为 External Target 或失去 Transform 时能安全结束。
- [ ] 回放和网络场景下，同一请求序列产生一致的移动结果。
- [ ] 大量实体同时执行曲线、碰撞和阻挡时不发生每实体动态内存分配。

## 建议实现顺序

1. 先补默认 Kinematic Adapter 和高速移动的连续碰撞 / 子步进验证。
2. 再增加预编译的 `EaseIn`、`EaseOut`、`EaseInOut` 位移曲线。
3. 之后增加加速度模型和抛物线轨迹，统一移动进度与终点校正。
4. 最后评估动态目标跟随、通道化组合和外部移动系统适配。
